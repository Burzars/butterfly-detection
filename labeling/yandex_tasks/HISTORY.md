## Почему возникали новые версии

- **v3 / refresh_pools.py.** Начальные незапущенные черновики переведены на обновлённую схему; bbox основной получил подмешивание 4 рабочих + 1 контрольного. Старые этапы 6868883–6868888 заменены на 6869459–6869464. Основной bbox тогда 6869461, основной review 6869464.
- **no-skip-v4 / separate_skip_by_stage.py.** Разделены интерфейсы: в обучениях/экзаменах «Пропустить» выключено, в основном сохранено. Новые bbox обучение 6869964, экзамен 6869966; review обучение 6869967, экзамен 6869968. Основные пулы не менялись.
- **learning-v5 / setup_bbox_learning.py, finalize_bbox_learning_pages.py, publish_bbox_learning_ui.py.** Bbox обучение стало самостоятельной первой попыткой с показом эталона после ответа и внешним порогом 7/8. Навык 21744; цепочка пробных ID 6870004 → 6870005 → 6870012. Итоговая организация — 8 отдельных страниц в обычном разделе pools.
- **clear-fix / fix_bbox_deleted_regions.py.** После удаления последней рамки поле становится пустым, а прежняя JSON Schema это отклоняла. Использована `condition.empty`; положительный ответ без рамок по-прежнему запрещён. Bbox основной 6869461 → 6870095, экзамен 6869966 → 6870099. Обучение тогда 6870012.
- **two-answers / remove_bbox_image_error.py.** Удалён ответ «Изображение не загрузилось» и технический комментарий. Конечные bbox: основной **6870107**, экзамен **6870108**, обучение **6870109**. Для review аналогичное удаление выполнено `remove_review_technical_answer.py`; основной стал 6870238, экзамен оставался 6869968, обучение 6869967. Широкие allowed_values в схеме могут сохраняться для совместимости, но видимых вариантов стало два.
- **review first-verdict / setup_review_learning_gate.py.** Обучение review перенесено в бесплатный пул **6870548**, введён навык **21790** и проход 7/8 первых бинарных вердиктов; эталон показывается после ответа. Старое native-обучение 6869967 архивировано. Поле `understood` осталось техническим, автоматически выставляется; отдельного подтверждения прочтения больше нет.
- **binary-verdict / review_verdict_only.py.** Из экзамена и основного review удалены причины ошибок и комментарии. Из-за закреплённых версий созданы конечные экзамен **6870571** и основной **6870574**. Старые 6869968 и 6870238 архивированы. Оценивание только по `status`; экзамен 11/12, основной скрытый контроль последних 10 ответов с порогом 80%.
- **19.11, добор.** У единственной существующей страницы экзамена review перекрытие увеличено с 10 до 13: добавлено ровно 3 попытки. Других страниц не создавали, критерий не меняли. Экзамен и основной review завершены.
- **19.11, завершение.** По просьбе пользователя закрыто бесплатное обучение review 6870548; статус `CLOSED` подтверждён API. Новые попытки/работы не запускались.

В Яндекс Заданиях пул закреплён за версией интерфейса. Текущий проект мог снова содержать обучение, пока рабочие пулы использовали прежние версии. Поэтому предупреждение «неактуальная версия проекта» было ожидаемым. Снимки рабочих `view_spec` сохранены отдельно в `ui/`, а не восстановлены из сегодняшней версии проекта.

## Исходные скрипты в historical_scripts/

- `build_projects.py` — первоначальные проекты, навыки, пулы и интерфейсы; `upload_bbox.py` — 400 исходных фото; `upload_quality_examples.py` — учебные, экзаменационные и контрольные примеры.
- `upload_bbox_results_to_review.py` — ровно 400 принятых bbox-ответов в review, сохранение рамок и автора; `unavailable_for` запрещает автору проверять своё фото; перекрытие 2.
- `repair_review_exam.py`, `repair_remaining_antennae.py`, `repair_training_bounds.py` — корректировки эталонов и перенос исправленных примеров.
- Остальные миграции перечислены выше; они включены как исходный журнал реализации.

Эти скрипты исторические: рассчитаны на конкретные незапущенные черновики, снимки до миграции и соответствующие сохранённые payload. **Это не одна универсальная команда пересоздания текущих завершённых проектов.** Для восстановления они требуют отдельно уже имеющиеся у команды настройки, инструкции, исходные фото/ответы и журналы конкретного этапа. Полные выгрузки и `state/objects.json` намеренно исключены по запросу. Не подставлять сегодняшние ID вместо старых автоматически: они относятся к другой стадии. Без этих входов старые миграции могут остановиться на проверках. `build_projects.py` при создании новых черновиков создаёт свой рабочий `state/objects.json`; файл не нужен переносимому вычислителю допуска.

Переносимые скрипты допуска в корне `Яндекс_Задания/` и офлайн-пересчёт полностью работоспособны с вложенными политиками и эталонами; реальные ответы для пересчёта передаются из вашей отдельной выгрузки.
