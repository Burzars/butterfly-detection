# ДЗ5: код допуска bbox и материалы воспроизводимости

Собрано 19.11.2026 для передачи сокоманднику. Учётных данных в архиве нет. Все пути ниже считаются от распакованной папки `dz5_repro_2026-11-19`.

## Что включено

- `ДЗ5/Яндекс_Задания/bbox_exam_control.py`, `bbox_training_control.py`: тот же алгоритм проверки рамок и выдачи двух разных навыков, с переносимыми импортами и чтением токена.
- `test_bbox_exam_control.py` и `test_bbox_learning.py`: 7 + 4 = **11 исходных регрессионных тестов**.
- `configs/bbox_exam_scoring.json`, `bbox_training_scoring.json`: исходные политики, сохранены побайтно.
- `configs/runtime_ids.json`: только минимальные привязки аккаунта, проектов, пулов и навыков; заменяет зависимость проверяющего от отсутствующего `state/objects.json`. Эти идентификаторы не являются учётными данными.
- `portable_runtime.py`: общий API-клиент и вспомогательные функции, выделенные из исходного `hw2_api.py`; внешний репозиторий ДЗ2 не требуется.
- `fixtures/bbox_exam_suite.json`: только ID, состав и входные данные единственной экзаменационной страницы. Это фикстура для тестов и офлайн-пересчёта; ответов исполнителей в ней нет.
- `ДЗ5/Проверка_эталонов/`: четыре запрошенных файла с пользовательским оригиналом, проверенными эталонами и изменениями. Добавлены исходники подготовки/визуализации.
- `state/bbox_exam_results.json`, `bbox_training_results.json`: два запрошенных исторических отчёта, сохранены побайтно. Это решения локального проверяющего, не повторная выгрузка ответов исполнителей.
- `qualification_ui/training.{html,js,css}`, `review_learning_ui/lesson.{html,js,css}`: исходники обоих обучений.
- `ui/`: сохранённые интерфейсы всех шести конечных этапов и схемы входов/выходов. Рабочие интерфейсы и экзамены — **Template Builder JSON**, у них нет отдельного собственного HTML/JS/CSS. В `view_spec.json` сохранены исходный `config`, версии компонентов `lock` и настройки кнопок. Для classic-обучений сохранён `view_spec.json` и отдельные исходники. Происхождение — `ui/sources.json`.
- `historical_scripts/`: скрипты создания, загрузки и миграций, в том числе перенос bbox в review. Назначение и ограничения — `HISTORY.md`.
- `AI_ASSISTANCE.md`: явно отмечены изменения эталонных рамок и пояснений с помощью Codex.

Не включены токен, логин/пароль аккаунта, `.env`, исходные ответы исполнителей, полные выгрузки проектов/пулов/навыков, `instructions/`, `state/objects.json`, `audit_*.json`, `*_health.json`, `*_verified.json` и смета. Публичные имена авторов фотографий внутри неизменённых эталонов — сведения об источниках, не логин к аккаунту Яндекс Заданий.

## Python и зависимости

Проверено на **CPython 3.11.8**, macOS arm64. Проверка и тесты используют стандартную библиотеку. `fcntl` требует macOS/Linux; на Windows запускать в WSL. Библиотеки подготовки: **Pillow 13.0.0**, CA-сертификаты **certifi 2026.10.19** — версии фактически использовавшейся вспомогательной среды. Grader не использует Pillow; certifi используется при наличии, иначе стандартное доверенное хранилище SSL.

```sh
python3 --version
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cd ДЗ5/Яндекс_Задания
python -m unittest -v test_bbox_exam_control test_bbox_learning
```

Тесты не требуют токена, сети или доступа к платформе и не меняют исторические отчёты. JSON с эталонами должен остаться побайтно тем же: SHA-256 `35b7ed2d8c5797e0bea6bed4248fb6f523a466ce4d32cfe7daaa74c1c9e44dfb`. Изменение пробелов также меняет хеш.

## Пересчёт по вашим API-выгрузкам, полностью офлайн

Ваши исходные ответы уже выгружены отдельно, поэтому в архиве они не дублируются. Поддерживаются полный JSON-массив, JSONL либо одна полная API-страница `{items: [...], has_more: false}`. Пагинированную выгрузку сначала объединить. Запуск из `ДЗ5/Яндекс_Задания`:

```sh
python replay_bbox.py \
  --exam-assignments /путь/к/bbox_exam_assignments.json \
  --training-assignments /путь/к/bbox_training_assignments.json \
  --output reproduced_scores.json
```

Можно указать только одну из двух выгрузок. По умолчанию используется приложенная экзаменационная фикстура; `--exam-suite /путь/к/странице.json` позволяет взять вашу выгрузку той же страницы. Офлайн-команда не принимает работы, не выдаёт навыки и вообще не обращается к сети. Она воспроизводит оценки, но не подтверждает историческую выдачу навыка: сведения об этом есть в исходных отчётах и ваших выгрузках навыков. Число результатов зависит от момента снимка и полноты выгрузки.

## Работа с живым API

Для чтения и применения нужен действующий токен того же командного заказчика. Установить **одну** переменную `YANDEX_TASKS_TOKEN` (также поддерживаются `TASKS_TOKEN`, `TOKEN`) либо заполнить локальный `.env`. Чтобы использовать файл, из корня архива выполнить `cp .env.example .env` и отредактировать его самостоятельно. `.env` исключён из Git; Python читает его как текст, не исполняет. Архив содержит только пустой `.env.example`.

Из `ДЗ5/Яндекс_Задания`:

```sh
# Однократный пересчёт обучения и экзамена через API, без выдачи навыков и приёмки
python bbox_exam_control.py

# Однократно применить приёмку и допуски
python bbox_exam_control.py --apply

# Проверять оба этапа раз в минуту, применяя решения, до автоматического завершения
python bbox_exam_control.py --watch --apply
```

Даже без `--apply` локальные отчёты `state/bbox_*_results.json` перезаписываются актуальным расчётом: перед запуском сохранить копию исторических файлов. Для простого воспроизведения предпочтительна команда `replay_bbox.py` выше.

Обучение bbox: **7/8 первых зафиксированных ответов**, IoU ≥ 0,75 → учебный навык **21744=100**, открывающий экзамен. После ответа интерфейс показывает эталон при любом результате; он не подменяет сохранённый первый ответ. Экзамен bbox: **7/8**, IoU ≥ 0,75 → основной навык **21627=100**. Для пустого фото верны `empty` и отсутствие рамок. Для положительного фото должны совпасть количество объектов и максимальное взаимно однозначное сопоставление всех рамок; пропуски/лишние рамки запрещены. Порядок рамок не влияет. Тот же человек не допускается к противоположной роли review.

С `--apply` все завершённые экзамены принимаются и оплачиваются независимо от балла. Навык получает только прошедший. Повторный запуск не повторяет уже принятую оплату и существующую выдачу навыка. Скрипт сверяет аккаунт, проект, пул, страницу, изображения и хеш эталона. Изменённая привязка требует осознанного изменения `runtime_ids.json` и scoring-конфигов. Проверяющий не открывает пулы и не загружает задания. После завершения экзамена он может закрыть открытое обучение bbox, дожидается активных страниц и останавливается. Второй экземпляр блокируется через `fcntl`.

На дату передачи bbox уже завершён, локальный проверяющий остановился; запускать наблюдение для завершённой разметки не требуется. Review проверяется средствами платформы, этот локальный скрипт не управляет допусками review.
