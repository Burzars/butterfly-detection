# Golden set

`golden.jsonl` — итоговая проверенная разметка всех 400 фото. У каждого фото есть рамки или подтверждённое отсутствие бабочек (`"boxes": []`). Рамки — в долях кадра, как в Контесте:

```json
{"photo_id": 123, "boxes": [{"left": 0.1, "top": 0.25, "width": 0.3, "height": 0.5}]}
{"photo_id": 124, "boxes": []}
```

**Итог:** 400 фото, 248 рамок, 160 фото без бабочек.

## Как получен

Исходная разметка (Яндекс Задания, `labeling/bbox/raw/`) → два независимых вердикта ревью (`labeling/review/raw/`) → разбор спорных фото командой → сборка.
Правило и инструменты — в `labeling/golden_review/README.md`.

| Источник итоговых рамок | Фото |
|---|---:|
| Приняты без изменений (оба ревьюера «верно», с датасетом расхождений нет) | 337 |
| Разобраны командой: исправлены рамки | 31 |
| Разобраны командой: убраны рамки (на фото не бабочка) | 1 |
| Разобраны командой: подтверждены без изменений (из них ответ «бабочек нет» — 18) | 31 |

Изменено относительно разметчиков — 32 фото:
- на 10 фото разметчик ответил «бабочек нет», хотя бабочки есть (на одном из них — две);
- на 1 фото выделена одна бабочка из двух;
- на 1 фото как бабочка выделена оса;
- на 20 фото неточные границы: обрезаны крылья или лапки либо слишком много фона.

Исходная разметка исполнителей относительно golden: **F1@0,5 = 0,973** (precision 0,996, recall 0,952), **F1@0,75 = 0,944**.

## Файлы

- `golden.jsonl` — эталон для `eval/evaluate.py`.
- `golden_audit.jsonl` — по каждому из 400 фото: исходная разметка и автор, вердикты ревью (и заблокирован ли ревьюер правилом контроля), почему фото разбирали, решение, итоговые рамки, пояснение, кто решил, заменённые решения.
- `corrections.jsonl` — исправления, одна строка на фото:

      {"photo_id": 123, "before": [...], "after": [...], "decision": "fix", "reason": "пропущена вторая бабочка", "by": "человек", "decided_by": "...", "review_votes": [...], "review_flags": [...], "superseded": [...]}

  `by` — кто исправлял: `"человек"` или `"модель"`. Исправления моделью — не независимая человеческая проверка. В нашем golden все исправления сделаны людьми.
- `corrections.md` — те же исправления таблицей.

Файлы собирает `labeling/golden_review/build_golden.py`. Руками их не править: при ошибке поправить решение и пересобрать.

`qa_check.md` — проверка качества: что проверяли помимо ревью, найденные ошибки и как их нашли, чего проверка не покрывает.
